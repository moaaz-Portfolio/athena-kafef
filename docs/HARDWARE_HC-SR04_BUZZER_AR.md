# توصيل HC-SR04 والجرس مع ESP32-S3

## توزيع الأرجل في Firmware WiFi Radar 1.1.0

| الجزء | التوصيل |
|---|---|
| HC-SR04 VCC | مصدر 5V منظم |
| HC-SR04 GND | GND مشترك |
| HC-SR04 TRIG | GPIO 4 |
| HC-SR04 ECHO | GPIO 5 عبر مقسم جهد |
| Active Buzzer (+) | مصدر 5V |
| Active Buzzer (-) | مجمع ترانزستور NPN |
| GPIO 6 | مقاومة 1kΩ إلى قاعدة الترانزستور |
| باعث الترانزستور | GND |
| قاعدة الترانزستور | مقاومة 10kΩ إلى GND |

## مهم جدًا: حماية مدخل ECHO

خرج ECHO من HC-SR04 قد يصل إلى 5V، بينما مدخل ESP32-S3 غير متحمل لـ5V. لا توصّل ECHO مباشرة باللوحة.

استخدم مقسم جهد:
- مقاومة 1kΩ بين ECHO وGPIO 5.
- مقاومة 1.5kΩ بين GPIO 5 وGND.
- اجعل أرضي الحساس واللوحة مشتركًا.

الناتج يقارب 3V على GPIO 5 عند وصول 5V من ECHO.

## قيادة الجرس

استخدم Active Buzzer بجهد 5V مع ترانزستور NPN مناسب مثل 2N2222 أو BC547:
- موجب الجرس إلى 5V.
- سالب الجرس إلى Collector.
- Emitter إلى GND.
- GPIO 6 إلى Base عبر مقاومة 1kΩ.
- مقاومة 10kΩ بين Base وGND.

لا توصل الجرس مباشرةً إلى GPIO. استخدم مصدر 5V منظمًا مناسبًا للحساس والجرس، مع GND مشترك مع ESP32-S3.

## طريقة العمل

- يقيس الحساس المسافة بشكل دوري.
- يتم اعتبار وجود شخص عند الباب بعد قراءتين قريبتين داخل المسافة المحددة.
- يتم إلغاء حالة الوجود بعد ثلاث قراءات بعيدة أو بدون صدى لتقليل التذبذب.
- الجرس يصدر صفيرًا متقطعًا عند وجود شخص فقط إذا كان مفعّلًا من لوحة الجهاز.
- المسافة الافتراضية 100 cm، والحساس مفعّل افتراضيًا، بينما الجرس متوقف افتراضيًا حتى تفعيله من الويب.
- يرسل Firmware حالة الباب كل نصف ثانية إلى UDP على المنفذ `stream_port + 1`؛ الافتراضي 5006، لتستقبلها وحدة Python.

## القيود والاختبار

1. اختبر الحساس أولًا باستخدام جسم ثابت على مسافات مختلفة.
2. اختبر الجرس بعد التأكد من دائرة الترانزستور والـGND المشترك.
3. الأسطح المائلة أو القماش أو الأجسام الصغيرة قد تسبب قراءات غير مستقرة.
4. حساس HC-SR04 واحد يكتشف وجود جسم في مجال القياس، لكنه لا يحدد اتجاه الدخول والخروج بشكل موثوق.
5. هذا حساس اقتراب تجريبي، وليس إنذار اقتحام معتمدًا أو نظام أمان.
