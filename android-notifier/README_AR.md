# تطبيق WiFi Radar لأندرويد

هذا التطبيق يراقب **وحدة المعالجة المحلية** التي تشغّل Python User Edition، وليس ESP32-S3 مباشرة. يستعلم عن واجهة Python المحلية كل 3 ثوانٍ ويصدر إشعارات حسب الإعدادات المحفوظة على الجهاز.

## الإعداد لأول مرة

1. شغّل WiFi Radar User Edition على جهاز المعالجة.
2. افتح لوحة الويب على نفس جهاز المعالجة.
3. انسخ رمز الربط المحلي من لوحة الويب.
4. ثبّت APK على الهاتف.
5. أدخل عنوان جهاز المعالجة، مثل http://192.168.1.100:8000.
6. ألصق رمز الربط.
7. اضغط مزامنة الإعدادات، ثم احفظ أي تغييرات.
8. اسمح بإشعارات Android واضغط تشغيل المراقبة.

## أنواع الإشعارات

- اشتباه السقوط.
- الحركة.
- وجود شخص.
- تحول الغرفة إلى فارغة.
- وجود شخص عند الباب (بعد اكتمال ربط وحدة الباب).
- انقطاع اتصال الجهاز.
- انخفاض جودة CSI.

إعدادات الأنواع مشتركة مع لوحة الويب. إيقاف نوع إشعار لا يوقف الاكتشاف أو سجل الأحداث.

## Buzzer

يوجد خيار تفضيل Buzzer في التطبيق لتجهيز الإعدادات المستقبلية. لا يصدر هذا الخيار صوتًا فعليًا بعد؛ ما زال يلزم استكمال Firmware وربط عقدة الباب ESP32 + HC-SR04 + Buzzer، ثم ربط حدث وجود الشخص عند الباب بمخرج الصوت. يظل الخيار معطلًا افتراضيًا إلى حين اكتمال ذلك.

## الشبكة والخصوصية

- يجب أن يكون الهاتف وجهاز المعالجة على الشبكة المحلية نفسها.
- استخدم عنوان IP الخاص بجهاز المعالجة، وليس عنوان ESP32-S3.
- الرمز خاص بالجهاز؛ لا تشاركه مع أشخاص آخرين.
- لا تفتح منفذ واجهة المعالجة على الإنترنت ولا تستخدم تحويل منافذ الراوتر.
- المراقبة المحلية تعمل دون إنترنت ما دام الهاتف وجهاز المعالجة متصلين بالشبكة المحلية.
- الإشعارات إلى هاتف خارج المنزل أو خارج الشبكة تحتاج خدمة Push خارجية؛ هذا الإصدار يستخدم polling محليًا ولا يوفر Push عن بُعد.

## البناء

1. افتح مجلد android-notifier في Android Studio.
2. نفّذ Gradle Sync.
3. من Build اختر Build APK(s).
4. ثبّت APK الناتج واسمح بالإشعارات.

خدمة المراقبة تعمل في المقدمة أثناء تفعيلها؛ وقد تحتاج إلى استثناء التطبيق من تحسين البطارية حسب الهاتف وإصدار Android.
